2. Short Description
A decentralized collaborative savings protocol (ROSCA) on the Arc Network featuring an autonomous AI Liquidity Guardian. Roda digitizes peer-to-peer savings pools for SMEs using USDC escrows, default protections, and an AI risk engine to provide reputation-backed, under-collateralized borrowing on-chain.

6. Functional MVP and Diagram
Roda is a fully functional decentralized ROSCA (Rotating Savings and Credit Association) designed for SMEs to pool working capital on-chain. 1. Core Smart Contract (Arc L1): - Dynamic Collateral Withholding: Automatically calculates and locks the required collateral from won pots inside closeRound(), securing later rounds against defaults. - Late Default Deficit Protection: Intercepts defaulters' payouts in later rounds to automatically cover prior deficits and replenish the escrow pool. 2. AI Liquidity Guardian: An autonomous off-chain risk agent that monitors contract state. If a low-risk member defaults, the agent executes an on-chain bailout transaction using Circle's Developer-Controlled Wallets API to protect circle liquidity. 3. Dual-Wallet Security: To comply with the ReputationRegistry (ERC-8004) self-reporting restrictions, the AI Guardian separates transaction execution (Owner Wallet) from reputation logging (Validator Wallet). 4. L2 Agent Network (Simulation Layer): A client-side deterministic simulator modeling high-frequency transactions among 378 simulated agent wallets. This models how Roda matches high-volume micro-payments off-chain before settling back to Arc L1. 10. Circle Product Feedback
### Why we chose these products: ROSCAs require high-frequency, recurring micro-contributions (typically $10–$50) where standard EVM gas fees (often $0.20 to $1.50) make participation economically unviable. Arc’s sub-second finality and native USDC gas fees allow micro-deposits to retain 99.9% of their value on-chain. Furthermore, using USDC as the native gas token eliminates currency volatility risk for autonomous agents (such as our AI Liquidity Guardian), allowing the risk engine to budget execution fees deterministically without managing floating gas token prices. ### What worked well during development: - Sub-second Finality: Confirmation times under one second on Arc Testnet match the speed of Web2 banking interfaces. - Native USDC Gas: Eliminating volatile gas token management simplifies fee calculations and treasury operations. - Developer-Controlled Wallets: The MPC API makes automating on-chain operations for autonomous agents straightforward. ### What could be improved: - Lack of Pre-deployed Multicall3 Contract: Arc Testnet currently lacks a pre-deployed Multicall3 contract at the standard address (0xcA11bde05977b3631167028862bE2a173976CA11). Since standard React frontends built on Wagmi/Viem use multicall contracts to bundle read-queries, batch reads failed out of the box. We had to write a client-side parallel promise wrapper (multicallSafe) to bypass this, which increases RPC calls and code complexity. - ERC-8004 Registry Self-Feedback Reverts: The ReputationRegistry contract reverts self-feedback transactions to prevent sybil manipulation. This requirement was not explicitly documented, necessitating a dual-wallet validator design (Owner vs. Validator wallet) to successfully write logs. Clearer documentation of these registry constraints would save builders significant debugging time. ### Recommendations: - Pre-deploy Multicall3 at the standard address (0xcA11bde05977b3631167028862bE2a173976CA11) on Arc Testnet. - Provide official SDK helper templates or examples for multi-wallet autonomous agent validation patterns to greatly streamline development for agentic economy use cases.
